# 任务书：图片链路修复（表情包发送 + 图片识别）

> 目标版本：2.11.1（纯修复，不动功能面）
> 验收方：发布侧（本地构建 + 测试 + 真机行为）

---

## 一、问题与根因（已定位，不需要再查）

### 1.1 表情包经常发不出去

`MemeEntity` 只存 `url`。群里收图时存下的是 QQ CDN 的**带签名临时链接**（几小时失效、有防盗链）。
发送时走 URL 上传模式（`file_type=1` + `url`），**由腾讯平台服务器去拉这个链接**。

QQ 官方文档原文：

> URL 上传存在服务端下载失败的可能，若遇到下载失败，可先将资源下载到本地，再通过直接上传二进制数据的方式上传。

**症状特征**：刚收的图偶尔能发，存了几小时的图基本发不出去。

### 1.2 第二个坑：格式

官方图片类型只保证 **png / jpg**（软限 20MB）。表情包大量是 GIF / WebP：

- GIF 可能被压成静态帧或直接失败
- WebP 可能不被接受

### 1.3 图片识别不灵

两个独立原因，都要处理：

1. 视觉链路同样要先下载 QQ CDN 图片，URL 失效/防盗链时直接看不见图
2. `visionModel` 未填且 `baseUrl` 不含 "deepseek" 时，`modelForImage()` 会沿用主模型；而 `deepseek-chat` 不接受图片，表现为「完全看不见图」，且没有任何提示

---

## 二、修复方案（核心原则：不碰 URL，只传字节）

```
收图 → 下载字节 → 解码 → 转 JPEG（最长边 1024，质量 85）
     → 存 files/memes/<sha1>.jpg → 表里存相对文件名
发送 → 读本地文件 → base64 → file_data 直传（官方限 5MB）
识别 → 同样先下载转 JPEG → base64 给视觉模型
```

---

## 三、改动清单（按文件）

### 3.1 `botcore/.../api/OpenApi.kt`

新增二进制上传，保留 URL 上传作为回退：

```kotlin
/** 直接上传图片字节（file_data 模式），失败返回 null。 */
suspend fun uploadGroupImageBytes(groupOpenId: String, bytes: ByteArray): String?
suspend fun uploadUserImageBytes(userOpenId: String, bytes: ByteArray): String?
```

要点：

- 请求体：`file_type=1`、`file_data=<base64 字符串>`、`srv_send_msg=false`
- **`file_data` 的值是纯 base64**，不能带 `data:image/jpeg;base64,` 前缀
- 原始字节 **> 5MB 直接返回 null**（官方硬限制；base64 会再膨胀 33%，不要按编码后大小判断）
- 复用现有 `call()` 与 `retryOnAuthError`

### 3.2 数据库：`MemeEntity` 加本地路径

文件：`app/.../data/db/SocialEntities.kt`、`Entities.kt`

- `MemeEntity` 增加 `val path: String? = null`（**相对文件名**，不存绝对路径）
- 数据库 `version 16 → 17`
- `MIGRATION_16_17`：`ALTER TABLE meme_images ADD COLUMN path TEXT`
- 注册进 `AppDatabase.create()` 的 `addMigrations`
- `ConfigBackup` 只备份 `url/path` 元数据，**不备份图片文件本体**

### 3.3 botcore：转码接口（纯 JVM 不能依赖 Android API）

新增 `botcore/.../ai/ImageTranscoder.kt`：

```kotlin
/**
 * 图片转码：把任意格式的图片字节转成模型/平台都稳吃的 JPEG。
 * botcore 是纯 JVM 模块，不能 import android.graphics，实现由 app 侧注入。
 */
fun interface ImageTranscoder {
    /** 失败返回 null（调用方跳过，不阻断主流程）。 */
    suspend fun toJpeg(bytes: ByteArray, maxEdge: Int = 1024, quality: Int = 85): ByteArray?
}
```

### 3.4 app 侧：本地图片仓库

新建 `app/.../data/media/LocalImageStore.kt`：

- `download(url): ByteArray?` —— 带 UA，10 秒超时，拒绝 > 8MB（可复用 `RemoteImageLoader` 的下载部分）
- `transcodeToJpeg(bytes): ByteArray?` —— `BitmapFactory.decodeByteArray` → 等比缩放最长边 1024 → `Bitmap.compress(JPEG, 85)`；**GIF 解码默认取第一帧，这是预期行为**
- `save(bytes): String` —— 文件名用 SHA-1（同图去重），存 `filesDir/memes/`
- `read(name): ByteArray?`
- `trim()` —— 超过 200 个文件或 50MB 时按最后修改时间淘汰最旧的

### 3.5 收图链路

`MemeHarvester` 改为：

```
harvest(url) → download → transcode → save → 入库(url 记原始来源, path 记文件名)
任一环节失败 → 不入库（宁可不收，不要存一个用不上的链接）
```

### 3.6 发送链路（`BotRuntime.sendReply`）

解析出表情包标记后：

```
path 非空 → read 本地文件 → uploadGroupImageBytes → msg_type=7 发送
path 为空（老数据）→ 回退 URL 上传
两条都失败 → 只发文字（现状行为，不要报错）
```

### 3.7 视觉链路

`RemoteImageLoader` 增加转码：下载后先 `toJpeg` 再转 data URL。
实现方式：把 `ImageTranscoder` 注入进去，或者由 app 侧提供一个「下载 + 转码 + inline」的 `ImageInliner` 实现（后者更干净）。

### 3.8 设置页提示（`AiModelPage`）

当 `visionModel` 为空、且主模型是已知不接受图片的（`deepseek-chat` / `deepseek-reasoner`）时，
在视觉模型输入框下显示一行提示：「主模型不接受图片，请填写视觉模型（如 deepseek-flash）」。
不阻断保存。

## 五、坑清单（务必注意）

1. `file_data` 官方参数名就是这个，值是纯 base64，**不带前缀**
2. 5MB 是**原始字节**的硬限制，不是 base64 后的大小
3. `MemeEntity.path` 存**相对文件名**，Android 私有目录绝对路径在重装/迁移后会变
4. 老数据 `path` 为 null：走 URL 回退，失败就跳过，不能让整条回复失败
5. GIF 转 JPEG 取第一帧是可接受取舍（静态表情包 > 发不出去）
6. 图片文件不进 ConfigBackup（体积考虑）
7. 转码在 IO 线程，不要在协程主线程做 Bitmap 解码
