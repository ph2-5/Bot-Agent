# 任务书：可选向量化记忆（混合检索）

> 目标版本：2.15.0
> 前提：2.14.1（记忆检索层 + 场景契约）
> 数据库：20 → 21
> 核心原则：**用户配了 embedding 就用向量化，没配就退回纯倒排——默认行为一个字都不能变。**

---

## 一、要解决什么

现有 `memory_terms` 是中文二元组倒排，精确词匹配强（人名、梗、专有名词），但**语义召回为零**：

| 用户说的话 | 现有倒排 | 应有的结果 |
|---|---|---|
| 「上次说的那个游戏」 | 命中不了「原神」 | 命中「原神」相关记忆 |
| 「他是不是说要搬家」 | 命中不了「搬去杭州」 | 命中「张三：下个月搬去杭州」 |

补一层语义检索，但**必须可选**：不是每个用户都愿意再申请一个 API。

---

## 二、配置设计（关键：三层降级）

新增一组**独立的** embedding 配置（与主 AI 配置分开，各自独立）：

```kotlin
data class EmbeddingConfig(
    val enabled: Boolean = false,
    val provider: String = "siliconflow",   // siliconflow / zhipu / openai / custom
    val baseUrl: String = "",
    val apiKey: String = "",
    val model: String = "BAAI/bge-m3",
    val dim: Int = 1024,                    // 由"测试连接"自动探测后写入
    val timeoutSeconds: Long = 8,
)
```

三层降级（必须严格按顺序判断）：

| 状态 | 检索行为 |
|---|---|
| **未配置 / 开关关闭** | 纯倒排（**与 2.14.1 逐字节一致**） |
| 已配置且调用正常 | 倒排 + 向量 → RRF 融合 |
| 已配置但调用失败/超时 | 本次退回纯倒排，记日志；**连续失败 3 次自动暂停向量检索 10 分钟**，UI 提示 |

**API key 复用现有加密凭证存储**（`qbot_secrets`），不要明文写 DataStore。

### 预置 provider（填 key 即可用）

| provider | baseUrl | 默认模型 | dim |
|---|---|---|---|
| siliconflow | `https://api.siliconflow.cn/v1` | `BAAI/bge-m3` | 1024 |
| zhipu | `https://open.bigmodel.cn/api/paas/v4` | `embedding-3` | 2048（需确认） |
| openai | `https://api.openai.com/v1` | `text-embedding-3-small` | 1536 |
| custom | 用户填 | 用户填 | 测试后探测 |

**维度不能猜**：首次保存时调一次「测试连接」，用返回值长度写入 `dim`。探测失败则不允许开启。

## 三、数据层（20 → 21）

```sql
CREATE TABLE memory_vectors (
  kind TEXT NOT NULL,          -- FACT / ROOM / LORE / SLANG
  refId INTEGER NOT NULL,
  model TEXT NOT NULL,         -- 换模型必须能区分（维度可能不同）
  dim INTEGER NOT NULL,
  scopeKey TEXT NOT NULL,      -- 冗余存储，避免检索时 join 源表
  vec BLOB NOT NULL,           -- float32 小端，**已 L2 归一化**
  createdAt INTEGER NOT NULL,
  PRIMARY KEY(kind, refId, model)
)
CREATE INDEX index_memory_vectors_scope ON memory_vectors(scopeKey)
CREATE INDEX index_memory_vectors_kind ON memory_vectors(kind)
```

要点：

- **存的时候就归一化**（L2），检索只做点积，省一次 sqrt
- 序列化用 `ByteBuffer.order(LITTLE_ENDIAN).asFloatBuffer()`
- 1 万条 × 1024 维 × 4B ≈ **40MB**；384/512 维则 15MB。体积要显示在设置页

---

## 四、入库链路（异步，不阻塞回复）

新增记忆时（facts / room / lore / slang）：

```
消息处理完（原有流程不变）
  → 投递一条 embedding 任务（内存队列，不落库）
  → 后台协程串行消费：调 API → 归一化 → upsert memory_vectors
  → 失败：记日志，丢弃该任务（不重试，不回滚记忆本身）
```

**embedding 的输入粒度**（决定质量的一半）：

| 类型 | 输入拼接 |
|---|---|
| FACT | 事实原文（本身就是完整陈述） |
| ROOM | **滑动窗口 3 条 + 说话人**：`小明：... \n 你：... \n 小红：...` |
| LORE | `名称：备注` |
| SLANG | `词：含义。用法：例句` |

**不要对单条短消息 embedding**（"哈哈哈"的向量毫无信息）。

---

## 五、检索链路（RRF 融合）

```
MemorySearcher.recall(query, scopes, kinds, limit)
  ├─ 倒排（现有）：memories → rankA（按 rarity 排）
  └─ 向量（新）：异常处理
       · query 先查内存 LRU 缓存（同 query 60 秒内不重复调）
       · 调 embedding（超时 8s）→ 归一化
       · 暴力点积：`SELECT vec, refId FROM memory_vectors WHERE scopeKey IN (...) AND kind IN (...)` → 全扫 → rankB
  ↓
  RRF：score(d) = Σ 1/(60 + rank_i(d))，取 top (limit × 3)
  ↓
  交给现有 MemoryRanker（时间衰减/重要性/覆盖度）→ 最终 top-K
```

- **倒排不能删**：向量对专有名词不如关键词精确
- 暴力检索可接受：1 万条 × 1024 维 ≈ 1000 万次乘加，手机 20-50ms；5 万条以上才需考虑 HNSW
- 向量查询结果也要走 `scopeKey` 过滤（不能把 A 群的记忆召回给 B 群）

## 六、回填（存量数据）

新增「记忆向量化」后台任务：

- **不自动启动**：设置页手动点「开始向量化」，显示进度（`已处理 320 / 共 1500`）
- 分批：每批 20 条，批间隔 ≥ 1 秒（避免触发限流）
- 可中断：退出页面即停止，下次从断点继续（用 `NOT EXISTS memory_vectors` 查询剩余）
- 只处理有 scope 的记忆（facts/room/lore/slang），**不处理 ai_messages**（量大且价值低）

## 八、验收标准

### 自动检查

1. `:botcore:test` 全绿；`assembleRelease` 零错误
2. 新增测试：
   - **未配置时行为不变**：`MemorySearcher` 返回结果与 2.14.1 完全一致（同一组固定输入）
   - 余弦点积正确性（归一化后点积 = 余弦，误差 < 1e-5）
   - RRF 融合：同一文档在两个榜都靠前时排第一
   - `model` 不同时互不干扰（换模型不串数据）
   - 连续失败 3 次 → 进入暂停态，第 4 次不再调用
3. 迁移：20→21 后旧数据可读，`memory_vectors` 为空不影响检索

### 真机行为

1. **不配 API**：聊天、记忆注入、表情包全部与 2.14.1 一致（回归）
2. **配了 API**：群里说"上次说的那个游戏"，能召回「原神」相关记忆
3. **配了但 key 错误**：机器人正常回复（不卡顿、不报错），日志里有降级记录，UI 显示"向量检索已暂停"
4. **回填**：1500 条记忆，10 分钟内完成，可中断可续；进度与占用显示正确

## 九、坑清单

1. **归一化必须在入库时做**，检索时不要再 sqrt（省一半算力）。
2. **`model` 字段必存**：换模型后旧向量不可比，必须全量重算（UI 要提示）。
3. **维度不能猜**：必须用「测试连接」探测，猜错会导致点积维度不匹配直接崩。
4. **query 缓存**：同一句话 60 秒内不重复调 embedding（群聊里连续消息常重复）。
5. **失败要静默降级**：embedding 挂了绝不能影响回复，最多慢 8 秒——所以超时要短（8s），且要有连续失败熔断。
6. **scopeKey 过滤不能漏**：否则会把 A 群的记忆召回给 B 群（隐私 + 串味）。
7. **回填不要自动跑**：用户可能用流量、可能被限流，必须手动触发。
8. **不要给 ai_messages 建向量**：量大、价值低、还会把"聊天记录"整个语义化，成本失控。
