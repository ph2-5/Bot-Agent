# 任务书：从响应式到自主式（第一批）

> 目标版本：2.12.0（新能力，minor）
> 前提：图片链路任务（16→17）先合入；本任务占用数据库 17→18
> 边界：**只做 A 通道（对话中自主开口），不做 B 通道（群里完全安静时主动发起）**
> 产品形态：三档模式（OFF / PASSIVE / ACTIVE）**由用户选择**，默认 PASSIVE（= 现状），ACTIVE 需主动开启

---

## 一、要解决什么

现在的机器人是纯响应式：消息进来 → 判断该不该回 → 回。它没有"自己的状态"驱动行为。

已有的情绪值（`bot_mood`）、关系值（`affinities`）、内心戏（`inner_thoughts`）、插话反思（`chime_lessons`）目前**只影响回复的语气，不影响"要不要开口"**。

本任务把这条线接上：让机器人有一部分开口是**自己想要的**，而不是被叫的。同时必须学会**忍住**——自主式最容易翻车的不是不会说，是不会忍。

**但自主不能是默认行为**：不同群的容忍度差很多，所以能力做成用户可选的档位（见 4.6），默认保持现状。

## 三、核心设计

### 3.1 两道闸门

```
闸门一：想不想说（本地计算，0 API 成本）
    drive = base
          × interest     // 话题与人格/记忆的相关度      0.5 .. 1.5
          × mood         // 情绪值映射                  0.6 .. 1.4
          × closeness    // 与最近说话人的关系          0.7 .. 1.3
          × timing       // 距上次开口的衰减，太频繁惩罚  0.3 .. 1.2
          - interruptCost// 打扰成本：激烈对话中 / 刚被无视 / 深夜
    本地有素材（最近有对话 或 有未说出的内心戏）才进入计算，否则直接 HELD

闸门二：该不该说（一次便宜模型调用，只在 drive 过阈值时才发生）
    输入：最近 6-10 条对话 + 机器人的内心戏/情绪 + 人格摘要
    输出：SPEAK / HOLD + 一句话理由 + 想说的主题（不给正文）
```

两道闸门都通过，才用主模型生成正文（第三次调用）。

**成本控制**：绝大多数节拍只花本地计算；便宜模型调用每天上限 N 次（默认 120）；主模型生成只在真要开口时。

### 3.2 节拍器（两个触发源，不要只靠定时）

| 触发源 | 频率 | 作用 |
|---|---|---|
| 消息后顺带评估 | 每条群消息处理完后，**延迟 20-40 秒**随机 | 主路径。群里有对话时才可能想说 |
| 定时 tick | 每 10 分钟 | 兜底。让"沉默一段时间后突然接话"成为可能 |

消息后评估要**随机延迟**：立刻接话像条件反射，隔半分钟才像"想了想"。

### 3.3 A 通道怎么实现"主动开口"而不耗额度

**这是本任务的关键技巧**：自主开口时，如果群里有最近 5 分钟内的消息，就用**引用回复**（带 `msg_id`）的方式发出——
在用户看来是"它自己接了一句"，在平台看来是回复已有消息，**不消耗主动消息额度**。

只有"群里超过 5 分钟没人说话且 drive 极高"时才走真正的主动消息（第一批**不做**，留接口）。

### 3.4 忍住必须记账

每次 HELD 写一条记录（含话题指纹）。同一指纹连续 HELD 3 次 → 该话题冷却 30 分钟，不再重复想。
否则会出现"每 10 分钟想同一句话"的经典 bug。

## 四、改动清单

### 4.1 botcore 新增 `botcore/.../ai/AutonomousDrive.kt`

纯 JVM，无 Android 依赖，全部可单测：

```kotlin
/** 自主开口的输入状态。 */
data class DriveState(
    val mood: Int,                 // 0..100
    val interest: Double,          // 0..1，由调用方根据话题/记忆相似度给
    val closeness: Double,         // 0..1，与最近说话人的关系
    val minutesSinceLastSpoke: Int,
    val recentMessageCount: Int,   // 最近 10 分钟群消息数
    val ignoredCount: Int,         // 最近被无视的次数
    val hourOfDay: Int,
    val hasMaterial: Boolean,      // 有无可用素材（对话/内心戏）
)

enum class DriveOutcome { SPEAK, HOLD }

data class DriveDecision(
    val outcome: DriveOutcome,
    val score: Double,
    val reason: String,            // 用于日志与调试页
)

object AutonomousDrive {
    fun evaluate(state: DriveState, config: DriveConfig, nowMillis: Long): DriveDecision
}
```

打分规则写死在纯函数里，阈值来自 `DriveConfig`（可被设置页覆盖）。

### 4.2 botcore 新增 `AutonomousGate`（第二道闸门的接口）

```kotlin
/** 第二道闸门：由 app 侧用便宜模型实现。返回 null 表示这次不判断（当作 HOLD）。 */
fun interface AutonomousGate {
    suspend fun shouldSpeak(context: String, config: AuxAiConfig): AutonomousDecision?
}
```

注意：`AuxAiConfig` 已存在（记忆精排用的辅助模型配置），**直接复用**，不要新建配置类型。

### 4.3 app 侧新增 `AutonomousScheduler`

仿 `PersonaGrowthScheduler` 结构：

- `start()` / `stop()` / `tick()` / `force()`（force 供调试页手动触发）
- 消息后评估入口：`onMessageHandled(groupId: String)`，内部 `delay(random 20..40s)` 后评估
- 每机器人一个实例（多机器人架构下按 botId 隔离）
- 同一群 30 分钟内最多自主开口 2 次（硬上限，防话痨）

### 4.4 数据库（17→18）

### 4.5 BotRuntime 接入

- 消息处理完成后调用 `autonomousScheduler.onMessageHandled(groupId)`（不阻塞主流程）
- 自主开口时构造与被动回复相同的 `AiReply` 流程，但：
  - 提示词加一段「你不是被叫，是你自己想接一句」
  - 强制带 `msg_id` 引用最近的消息
  - 生成后仍走 `shouldHandle` 之外的**独立闸门**（不允许自主开口抢答已经被 @ 的消息）

### 4.6 设置页：三档模式，由用户选（本任务的**核心产品决策**）

不是"开/关自主"的二元开关，而是三档——因为「被动回复」和「主动插话」本来就是两种行为：

| 档位 | 行为 | 对应现状 |
|---|---|---|
| **OFF（纯响应）** | 只在被 @ / 叫名字 / 明确对话时回复；chime 与 drive 全关 | 最保守 |
| **PASSIVE（默认）** | 被叫必回 + 群里有明确话题时轻度插话（chime）；drive 关 | **= 2.11.x 的现状** |
| **ACTIVE（自主）** | PASSIVE + drive 驱动的自主开口 | 本任务新增 |

**关键约束**：

1. **默认必须是 PASSIVE**——老用户升级后行为零变化，不能"升级完突然开始自己说话"
2. ACTIVE 必须由用户主动选择，不能默认开
3. **支持按群覆盖**：全局设一个默认档，个别群单独设（A 群想活跃、B 群想安静是常态）
4. 切档**立即生效**：不用重启机器人、不用等下一个 tick
5. OFF 档下 drive 计算**完全不跑**（不是跑了再丢弃），保证零额外消耗

`SettingsRepository` 新增：

```kotlin
autonomyMode: String            // OFF / PASSIVE / ACTIVE，默认 PASSIVE（全局）
quietHours: String              // 如 "23:00-08:00"，ACTIVE 档下此区间只 HOLD
maxSpeaksPerHour: Int           // ACTIVE 档专用，默认 2
autoThreshold: Float            // 高级项，默认按档位给（见 4.1）
```

按群覆盖用一张小表（不塞进全局 settings）：

```sql
CREATE TABLE group_behavior (
  groupId TEXT PRIMARY KEY NOT NULL,
  autonomyMode TEXT NOT NULL,
  updatedAt INTEGER NOT NULL
)
```

`BotManagePage` 或群详情加一个"此群行为"下拉；`MemoryPage` 放全局默认。

阈值映射（ACTIVE 档）：LOW 0.75 / MEDIUM 0.62（默认）/ HIGH 0.45，供高级用户微调。

## 五、验收标准

### 自动检查

1. `:botcore:test` 全绿
2. `assembleRelease` 零错误、lint 零警告
3. 新增 `AutonomousDriveTest`，至少覆盖：
   - 无素材 → 必 HOLD
   - 深夜（quiet hours）→ 必 HOLD
   - 刚说完 1 分钟 → timing 惩罚生效
   - 情绪低 + 被无视 → HOLD
   - 情绪高 + 关系近 + 有素材 → 可能 SPEAK
   - 同一 fingerprint 连续 HELD 3 次 → 冷却
4. 迁移 DDL 与实体一致；17→18 可在旧库上执行

### 真机行为

1. **默认行为零变化**：全新安装 / 老用户升级后，不碰设置 → 行为与 2.11.x 完全一致（PASSIVE，不会自己开口）
2. 切到 **ACTIVE** 后：群里聊天时机器人**偶尔**（不是每条）自己接一句，且引用的是正在聊的内容
3. 连续 30 分钟观察：自主开口不超过 2 次
4. 深夜（安静时段）完全不自主开口
5. 切回 **OFF**：chime 与自主全部停止，只在被叫时回复
6. **按群覆盖**：A 群设 ACTIVE、B 群设 OFF，行为分别生效
7. 切档**立即生效**，无需重启
8. 调试页能看到每条自主决策的 score / outcome / reason（便于调阈值）

## 六、坑清单

1. **不要与 chime 抢答**：chime 管"这条消息值不值得接"，自主管"我想不想说话"。若某条消息已被 chime 判定为要回复，自主调度必须跳过该群本次节拍。
2. **不要立刻接话**：消息后评估必须随机延迟 20-40 秒，否则像反射不像思考。
3. **fingerprint 要归一化**：话题指纹用关键词/话题标签，不要用原文 hash（原文一变就不算重复）。
4. **多机器人隔离**：每个 botId 独立的 mood/决策表记录，别串。
5. **额度保护**：第一批全部走引用回复（不耗主动额度），但代码里要留 `proactiveSend` 的 TODO 注释，明确"这里会耗额度"。
6. **失败静默**：任何一次自主决策失败（模型报错/超时），只记日志，不影响正常回复。
7. **不要把 inner_thoughts 全量塞提示词**：只取最近 2-3 条未说出的。
