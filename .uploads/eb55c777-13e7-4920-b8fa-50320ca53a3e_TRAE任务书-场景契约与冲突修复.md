# 任务书：场景契约（AI 自生成）与场景冲突修复

> 目标版本：2.14.0
> 前提：2.13.0 已合入（场景语境 + 只读模式）
> 数据库：19 → 20
> 本任务两件事：**① 修三处场景与其他功能的冲突；② 让 AI 自己生成场景契约（语言约束），软件负责记录并执行**

---

## 一、要解决什么

### 1.1 现状的三个冲突（已定位，不要重新猜）

| # | 冲突 | 证据 | 后果 |
|---|---|---|---|
| C1 | **自主开口完全不看场景** | `AutonomousScheduler` 内 `grep scene` 零结果 | 场景等对方接话时，自主开口插一句 → 节奏断；场景刚说完，自主又接一句 |
| C2 | **OBSERVE 数据被自主污染** | 自主的 ACTIVE 档与场景 OBSERVE 互不感知 | 你以为在观察"AI 想怎么演"，实际群里还有自主发言混进来 |
| C3 | **`sceneMode` 是 per-bot，易误配** | `settings.sceneMode` 属于各自 `BotController` | 两个 bot 只切了一个 ACTIVE，演不起来，但没有任何提示 |

注：`chime` 与自主**已经**做了互斥（`BotRuntime.spokeAtMillis`），但场景没被纳入。

### 1.2 缺口：场景的语言约束是写死的

现在 `ScenePrompt` 是代码里的固定模板（"你演逗哏，每句留口子"），所有相声场景共用。

**目标**：AI 进入场景时**自己生成一份契约**（语言风格 / 角色规则 / 禁忌 / 收尾条件），存进数据库，之后每次场景内生成都注入这份契约。

这样"不同语境不同表现"不需要人写 N 套模板——**AI 自己写，软件负责记录与执行**。

## 二、第一部分：修三个冲突

### 2.1 自主开口让位于场景（C1）

`app/.../runtime/AutonomousScheduler.kt`

评估入口（`tick()` 与 `onMessageHandled()` 最终汇到同一处 `evaluateOnce`）：

```
评估前先查：
  1. 本群是否有 ACTIVE / WAITING 场景 → 有则跳过本次节拍
  2. 本群场景结束时间距今 < 5 分钟 → 也跳过（避免"相声刚完，它又自己开口"）
  3. 命中跳过时，写一条 autonomous_decisions(outcome=HELD, reason="场景进行中/刚结束")
```

需要注入 `SceneStore`（或由 `BotController` 提供一个 `hasActiveScene(groupId): Boolean` 回调）。**注意避免循环依赖**：优先用回调 `() -> Boolean`，不要直接依赖 store 实现。

### 2.2 OBSERVE 档下自主只记录不发言（C2）

同一处入口：

```
sceneMode == OBSERVE 时：
  · 照常跑 drive 打分与两道闸门（保留观察价值）
  · 决策写入 autonomous_decisions，标注 suppressedBy = "SCENE_OBSERVE"
  · 不实际发送
```

这样 OBSERVE 期间群里的行为完全不受自主影响，观察数据干净。

### 2.3 per-bot 配置提示（C3）

`MemoryPage`（场景档位所在页）顶部加一行提示：

> 场景档位按机器人独立设置。双人演出需要**两个机器人分别设为 ACTIVE**。

不阻断保存，只提示。

## 三、第二部分：场景契约（SceneContract）

### 3.1 数据结构（`botcore/.../ai/SceneContract.kt`，纯 JVM）

```kotlin
@Serializable
data class SceneContract(
    /** 语言风格：口音/语体/句长/称呼方式 */
    val languageStyle: String = "",
    /** 角色名 → 该角色的行为规则 */
    val roleRules: Map<String, String> = emptyMap(),
    /** 禁忌（最多 5 条） */
    val taboos: List<String> = emptyList(),
    /** 收尾条件 */
    val exitCriteria: String = "",
    /** 可用的素材/话题（可选，最多 3 条） */
    val props: List<String> = emptyList(),
) {
    /** 字数上限截断，防止 AI 写成长文把提示词撑爆 */
    fun normalized(): SceneContract
    fun isEmpty(): Boolean
}
```

**硬性长度限制**（在 `normalized()` 里执行，不是提示词里请求）：

| 字段 | 上限 |
|---|---|
| languageStyle | 120 字 |
| roleRules 每条 | 80 字；角色最多 4 个 |
| taboos | 每条 40 字，最多 5 条 |
| exitCriteria | 80 字 |
| props | 每条 40 字，最多 3 条 |

超出部分截断并加省略号——**宁可截断，不要让它把上下文吃掉**。

### 3.2 生成：跟着 `start_scene` 一起给

`start_scene` 工具的参数扩展：

```json
{
  "kind": "crosstalk",
  "role": "comedian",
  "partnerName": "于谦",
  "goal": "说一段关于'减肥'的相声",
  "contract": {
    "languageStyle": "京津口语，短句为主，多用'您'，避免书面语",
    "roleRules": {
      "郭德纲": "抛话题、铺包袱，每句留口子；不许自己接自己的包袱",
      "于谦": "台词不超过 20 字，主要用'是吗''您给说说''去你的吧'"
    },
    "taboos": ["不提政治", "不拿家人做人身攻击"],
    "exitCriteria": "抖完最后一个包袱，说'今天就到这儿'收尾"
  }
}
```

**工具描述里必须写清**：

> contract 是你为这次演出写的规则，要具体、可执行。不要写"要自然""要幽默"这类空话。
> 角色规则要写清"谁能做什么、不能做什么"，而不是形容词。

### 3.3 存储

`scenes` 表加一列（migration 19→20）：

```sql
ALTER TABLE scenes ADD COLUMN contractJson TEXT
```

`Scene` 模型加 `contract: SceneContract?`。老场景为 null → 回退固定模板。

### 3.4 注入（`ScenePrompt.block`）

优先级：

```
contract 存在且非空 → 渲染契约
否则              → 现有固定模板（行为与 2.13.0 一致）
```

渲染格式（**放在人格之后、记忆之前，保持前缀稳定以命中缓存**）：

```
[场景契约]
语言风格：京津口语，短句为主，多用"您"，避免书面语
你的角色（郭德纲）：抛话题、铺包袱，每句留口子；不许自己接自己的包袱
对方（于谦）：台词不超过 20 字，主要用"是吗""您给说说""去你的吧"
禁忌：不提政治；不拿家人做人身攻击
收尾：抖完最后一个包袱，说"今天就到这儿"收尾

（契约在这个场景内保持不变，不要中途改写规则）
```

最后一句很重要——防止模型在场景中途"即兴改设定"。

### 3.5 contract 不进记忆、不进备份

契约属于场景数据（`scenes` 表），随场景结束失效，**不要**写进 `facts` / `lore` / ConfigBackup。

## 五、验收标准

### 自动检查

1. `:botcore:test` 全绿；`assembleRelease` 零错误
2. 新增 `SceneContractTest`：
   - 超长字段被截断到上限
   - `isEmpty()` 判定（全空时回退旧模板）
   - 序列化 → 反序列化往返一致（含中文、换行）
   - `MIGRATION_19_20` 后旧行 `contractJson` 为 null 不崩

### 真机行为

**冲突修复**

1. 开场景（ACTIVE）+ 开自主（ACTIVE），场景 WAITING 等对方 30 秒 → **自主不插话**
2. 场景结束后 5 分钟内 → 自主也不开口
3. 场景 OBSERVE + 自主 ACTIVE → 群里只有自主按原逻辑说话；`autonomous_decisions` 里能看到 `suppressedBy=SCENE_OBSERVE` 的记录

**场景契约**

4. 触发一场相声 → 调试页能看到 AI 生成的契约（具体、可执行，不是"要自然"这种废话）
5. 对话内容明显符合契约（比如"于谦台词不超过 20 字"→ 实际台词确实短）
6. 老场景（2.13.0 建的，contract 为 null）→ 行为与 2.13.0 一致

## 六、坑清单

1. **别让 AI 自由发挥写契约**：工具 schema 里必须给出字段说明和示例，否则它会写一段散文，塞不进结构。
2. **截断必须在代码里做**，不能只靠提示词——模型不会老实遵守字数。
3. **契约位置要固定**（人格之后、记忆之前），否则前缀缓存失效，每轮都全量重算。
4. **不要允许场景中途改契约**：提示词里写死"契约不变"，第一期不做 `update_contract`。
5. **自主让位的判断要查"本群"**，不是全局——A 群演戏不该影响 B 群的自主。
6. **OBSERVE 的判断不能省**：C2 的修法是"照常评估、只不发送"，而不是"直接跳过"——否则观察数据有洞。
7. **per-bot 配置的坑要在 UI 明说**，别指望用户自己发现。
