# QBotMobile — 手机端 QQ 机器人（官方开放平台）

> **当前版本 2.9.0** · 会聊天、会挑表情包、会联网搜索、能看图、有人格成长与世界书、支持文件式语气插件

在 Android 手机上 **24 小时运行 QQ 机器人**，同时把手机当作 **维护端**（看状态、看日志、改规则、手动发言）。

不使用任何第三方协议库（NapCat / Lagrange / Shamrock），也不需要 root、Termux 或 Xposed ——
走的是 **QQ 官方机器人开放平台**，纯 HTTPS + WebSocket，一个普通 App 的前台服务即可长期在线。

> 官方明确说明：WebSocket 模式「不依赖公网服务器部署，适合个人单机使用，需维护长连接」。
> 这正是手机端场景的正确选择。

---

## 一、为什么这样设计

| 需求 | 方案 | 理由 |
|---|---|---|
| 手机 24h 在线 | 官方 WebSocket 模式 + 前台服务 | 不需要公网 IP，也不需要 root |
| 数据存在手机里 | Room 存日志与规则，Keystore 存凭证 | 离线可用，换设备导出即走 |
| 手机当维护端 | Jetpack Compose 五页维护界面 | 状态、日志、规则、AI（记忆/人设）、设置一个 App 搞定 |
| 不想用 OpenClaw | 自己实现机器人逻辑 | OpenClaw 是官方提供的 AI Agent 接入服务，本项目走"原创机器人"路线 |

### 关于「第三方协议」的说明

第三方协议端（NapCat 等）功能更全，但属于非官方协议，存在封号风控风险。
本项目**刻意只支持官方开放平台**，换来的是零风控、零 root、长期稳定。这是有意取舍，不是遗漏。

## 二、安装（最简方式）

**仓库不带成品 APK，也不带签名密钥**（公开仓库泄露签名密钥等于把应用的身份交出去）。

**方式零：直接下载已发布版本（最省事）**

到 [Releases](https://github.com/ph2-5/Bot-Agent/releases) 下载最新的
`QBotMobile-x.y.z-release.apk`，传到手机安装即可。Release 包已用项目正式密钥签名，
后续版本可直接覆盖升级。

**方式一：GitHub Actions 云构建（零本地环境）**

1. Fork 或 Clone 本仓库到自己的 GitHub；
2. 仓库页面 → **Actions** → 「Build APK」→ **Run workflow**；
3. 等 3-5 分钟，在运行记录底部的 **Artifacts** 里下载 `QBotMobile-release.zip`；
4. 想用自己的签名（与旧版本覆盖安装需一致）：仓库 **Settings → Secrets and variables → Actions**
   添加 `KEYSTORE_BASE64`（`base64 -w0 your.jks` 的输出）与 `STORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`，
   下次构建会自动签名；不配则产出未签名包，需自行 `apksigner` 签名后才能安装。

**方式二：本地构建**

```bash
./gradlew assembleRelease        # 需要 JDK 17 + Android SDK 35
                                   # 产物在 app/build/outputs/apk/release/
```

要求：JDK 17、Android SDK（platforms;android-35、build-tools;34.0.0+），最低支持 **Android 8.0（API 26）**。

装完打开 → **设置** 页填入 AppID 与 AppSecret → 保存 → 回 **状态** 页点「启动机器人」。
想用 AI 就在 **设置 → AI 接入** 里填服务地址 + API Key + 模型名，点「测试连接」验证通过后保存。
**「AI」页**管理记忆（谁是谁、记住了什么）和人设（对不同人/群说不同的话）。

### 申请机器人凭证

1. 打开 [QQ 开放平台](https://q.qq.com/#/apps) 注册并完成**主体认证**（个人开发者需实名）。
2. 创建机器人，在管理端拿到 **AppID** 和 **AppSecret**。
3. 开发设置里把「事件订阅与回调方式」切换为 **WebSocket**。
4. 服务范围：未认证时机器人仅管理员可用，可添加到**你作为群主**的群里测试。

```

│       ├── engine/         规则引擎、运行时、日志
│       ├── ai/             AI 应答、缓存友好组装、记忆管线、人设解析、群感知
│       └── model/          协议报文与消息模型
├── app/                    Android 壳
│   └── src/main/kotlin/com/qbot/app/
│       ├── service/        BotForegroundService + ResurrectorJobService（保活）
│       ├── network/        NetworkMonitor（网络恢复监听）
│       ├── receiver/       BootReceiver（开机 / 升级后自启）
│       ├── runtime/        BotController（生命周期与依赖组装）
│       ├── data/           Room 数据库 + 加密设置仓库
│       └── ui/             Compose 维护端（状态 / 日志 / 规则 / AI / 设置）
```

**`botcore` 与 Android 解耦**是核心设计：协议层可以脱离模拟器直接跑测试，
将来也能搬到服务器或桌面端复用同一套引擎。

## 四、协议实现要点

```
取凭证 → 取网关 → 建连 → Hello(10) → Identify(2)/Resume(6) → READY(0)
                                   → 心跳(1) ⇄ ACK(11) → 断线退避重连 ↺
```

| 环节 | 接口 |
|---|---|
| 取凭证 | `POST https://bots.qq.com/app/getAppAccessToken` |
| 鉴权头 | `Authorization: QQBot {access_token}` |
| 取网关 | `GET https://api.sgroup.qq.com/gateway/bot` |
| 心跳周期 | Hello 下发，默认 45s |
| 断线续传 | `op6 Resume {session_id, seq}`，平台补发遗漏事件 |

### 针对 7x24 挂机做的加固

1. **心跳僵死检测**
   移动网络下 TCP 会进入"半开"状态——既不报错也收不到数据（Wi-Fi 切 4G、进电梯、NAT 老化）。
   如果只看心跳是否发出，机器人会"看起来在线"实则掉线数小时。
   因此额外监控 ACK 是否逾期，超过 `心跳周期 × 2.5` 即判定僵死并主动重连。

2. **带抖动的指数退避**
   `delay = min(1s × 2^n, 30s) × (1 ± 20%)`。抖动用于打散重连时刻，避免重连风暴。

3. **错误码分流**
   `4009` → Resume 保留会话；`4914`（已下架）/ `4915`（已封禁）→ 直接停机；
   其余 → 重新 Identify。**封禁时不再无意义地反复重连耗光电量。**

4. **Intents 四级降级**
   Identify 被服务端拒绝（关闭码 4013/4014 或 op9 Invalid Session）时，
   按 `完整订阅 → 去掉群成员事件位 → 仅消息事件 → 基础事件` 逐级降级重连，
   尽量保住「群@/单聊」能力；全部被拒才停机并提示去平台申请权限，绝不无脑重连。

5. **连接纪元（epoch）**
   每次新建连接递增，所有异步回调先校验纪元再处理，避免旧连接的迟到回调污染新连接状态。

6. **凭证提前刷新**
   凭证寿命 7200 秒，提前 5 分钟换新；OpenAPI 返回 401 时立即作废并重试一次。

7. **网关地址缓存 + 限频冷静期**
   `GET /gateway/bot` 限频严格，取到地址即缓存复用；万一触发限频，
   重连间隔自动拉长到分钟级（60-120s），不再秒级撞墙。

## 五、保活：这是最现实的一关

技术上机器人能跑，但**国产 ROM 会杀后台**。本项目做了多层保险：

| 层 | 机制 |
|---|---|
| 前台服务 | 常驻通知（用户可一键停止），`START_STICKY` 让进程被回收后系统尝试重建 |
| 定时复活 | `JobScheduler` 每 15 分钟唤醒一次，发现服务不在就重新拉起；`setPersisted(true)` 跨重启保留，进程整体被杀也能到点复活 |
| 开机自启 | `BootReceiver` 监听开机 / 升级广播（含华为等机型的 QUICKBOOT），顺带确保复活任务已注册 |
| 网络监听 | `ConnectivityManager.NetworkCallback` 动态监听，恢复后延迟 1.5s 重连 |
| WifiLock | `WIFI_MODE_FULL_HIGH_PERF`，避免系统在灭屏后限制 Wi-Fi 流量 |
| 重连 WakeLock | 进入重连流程的瞬间点亮的短超时（15s） WakeLock，保证退避等待到期后能立刻抢到 CPU 发包 |
| 看门狗 | 每 60s 校验，发现控制器停止且用户未主动停止则重新拉起 |
| 存活统计 | 记录「最近是谁把机器人拉起来的」（手动/开机/定时复活/系统重建），仪表盘可见——**复活次数持续上涨就说明 ROM 在杀你** |

> 注：Android 7.0 起静态注册的 `CONNECTIVITY_CHANGE` 广播不再回调，
> 因此**没有**在 Manifest 里声明网络广播接收器，改由服务内动态完成。

**你还需要手动做的两件事**（App 内有引导入口）：

1. 把本应用加入**电池优化白名单**（系统不允许应用自行豁免，必须用户在系统页确认）
2. 在系统设置里允许**自启动 / 后台运行**（MIUI、ColorOS、EMUI 位置各不相同）

仪表盘「ROM 保活指南」卡片按厂商给出了路径，并可一键跳转自启动管理页
（小米/华为/OPPO/vivo/三星，跳不动的机型退到应用详情页）。

做完这些，常规机型可稳定在线数天到数周；**但没有任何 App 能 100% 对抗国产 ROM 的
内存管理**——定时复活的意义就在于：即使被杀了，最多 15 分钟后它自己回来。

## 六、规则引擎

内置轻量自动回复，规则存本地数据库，**修改后无需重启机器人**（下一次消息即生效）。

- 匹配方式：`EXACT` 全等 / `CONTAINS` 包含 / `PREFIX` 前缀 / `REGEX` 正则
- 作用范围：`ALL` / `GROUP_ONLY` / `PRIVATE_ONLY`
- 优先级：数值越大越优先，命中后即停止匹配
- 回复变量：`{content}` 用户原话、`{sender}` 发送者、`{target}` 群/用户、`{time}` 时间、`{nl}` 换行

正则非法时会被安全跳过（不会导致崩溃）。

## 六·补、AI 接入

在「设置 → AI 接入」里填三项即可对话，走 **OpenAI 兼容协议**，一套配置通吃：

| 服务 | 地址 | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| OpenAI | `https://api.openai.com` | `gpt-4o-mini` |
| 本地 Ollama | `http://电脑IP:11434` | `qwen2.5` |

- **地址容错**：填 `https://api.deepseek.com`、带 `/v1` 或完整路径都能识别，不会因为差一个 `/v1` 就 404
- **API Key 加密存储**（Android Keystore），与机器人凭证同一套加密方案
- **三种触发方式**：
  - `规则优先`（默认）：本地规则未命中才问 AI，关键词与 AI 混用
  - `AI 优先`：所有消息都走 AI，本地规则暂时失效
  - `仅 /ai`：只有 `/ai 开头`的消息才触发，其余按规则处理
- **多轮上下文**：按**人**隔离记忆（同一个群里 A 和 B 的历史互不串台），默认保留最近 6 轮，重启不丢失（Room 落库）
- **失败兜底**：AI 出错时按配置的话术回复（如"AI 暂时无法回答"），留空则不回复
- **清空上下文**：发送 `/ai 清空`（或 `新对话`）重置当前会话记忆
- **保存即生效**，无需重启机器人；「测试连接」按钮可在群里来消息前先验证 Key 是否正确

常见错误码已翻译成中文：401 → Key 无效、404 → 地址或模型名不存在、429 → 频率超限或额度不足。

### 响应速度与成本控制（1.2.2 起）

| 功能 | 说明 |
|---|---|
| **思考模式开关** | DeepSeek **默认开启思考**（先输出思维链再作答），这是"感觉慢"的主因。设置页默认**关闭**，关闭后请求体带 `{"thinking":{"type":"disabled"}}` 直接出答案；该参数仅对 DeepSeek 端点发送（OpenAI 等严格服务商遇未知字段会 400） |
| **提示词 token 可见** | 系统提示词输入框下方实时显示估算 token 数，超 1500 变红警示——提示词每轮全量发送，越长越贵越慢 |
| **上下文 token 预算** | 滑块控制「提示词 + 历史 + 本轮问题」总量上限（默认 3000）。超限时从最早的对话**成对丢弃**；服务端仍报超限（400 context length）会自动砍半重试一次 |
| **缓存友好组装** | system 提示词固定最前、内容逐字节稳定、历史只追加不重写。DeepSeek 前缀缓存要求「从第 0 个 token 起完全相同」，命中部分价格仅 1/10，首字延迟大幅降低（128K 场景实测 13s → 500ms） |
| **用量与命中率** | 仪表盘 AI 卡片显示最近一次请求的 token 总数、缓存命中率、回复 token；命中率长期为 0 说明提示词被动态内容污染，值得排查 |

## 六·补二、记忆系统（1.3 起）

机器人不只是"会聊天"——它**认识群里的每一个人**，并按人组织记忆。

### 身份识别：群聊里谁在说话

QQ 官方开放平台**不提供群成员昵称查询接口**，所以展示名按优先级从三个渠道获得：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 3（最高） | 维护端手动备注 | 「AI」Tab → 记忆 → 点人名改名，永不被覆盖 |
| 2 | 用户自称 | 对机器人说「叫我 XX」自动学习 |
| 1（最低） | 平台自带昵称 | 事件 payload 里的昵称（部分事件才有） |

低优先级永远不能覆盖高优先级；日志与 AI 看到的都是**展示名**而非一长串 openid。

### 三层记忆结构

| 层 | 内容 | 作用域 |
|---|---|---|
| 工作记忆 | 与每个人的最近 N 轮对话原文 | **按人隔离**（群聊里 A 的历史不会进 B 的上下文） |
| 群聊背景 | 群里最近的消息摘要（含他人发言） | **按群共享**——这样机器人能理解「那他呢」这类跨人指代 |
| 长期事实 | 从对话中抽取的个人信息（喜好、身份、约定） | 按人存储，每人默认上限 50 条，超出按时间淘汰 |

组装请求时严格按 `人设(system) → 事实(system) → 群背景(system) → 历史(对话) → [展示名] 问题(user)`
的顺序拼接——system 部分逐字节稳定，DeepSeek 前缀缓存命中率才有保障。

### 用户侧指令（在群里直接对机器人说）

- `叫我 XX` —— 设置/更新在该群的展示名
- `我的记忆` —— 查看机器人记住了你的哪些事
- `忘掉 XX` —— 删除某条事实；`忘掉全部` 清空你的一切记忆（历史与事实都清）

这些指令的**执行**在本地完成（改名片、删记忆都是数据库操作），
**回复**则由 AI 按人设语气生成（见「指令回复的人设化」），不再使用固定句式。

维护端在 **「AI」Tab → 记忆** 里可以：看每个人记住了什么、手动改名、删除单条事实、
一键"忘掉全部"，以及总开关 / 每人条数 / 群背景大小 / 指令人设化等配置。

## 六·补三、人设系统（1.3 起）

同一台手机上的机器人可以**对不同人、不同群说不同的话**：

| 作用域 | 优先级 | 典型用途 |
|---|---|---|
| 按人 | 3（最高） | 对管理员用严谨口吻，对常聊的群友用吐槽口吻 |
| 按群 | 2 | 工作群严谨、水友群放飞 |
| 全局 | 1（兜底） | 默认人设，就是「AI 接入」里的系统提示词 |

人设条目在 **「AI」Tab → 人设** 里增删，可绑定到具体的人（从"最近互动的人"里选）或具体的群。
解析顺序：先看有没有按人绑定的，再看按群，最后回落到全局——完全没配人设时行为与旧版一致。

人设提示词与记忆事实**分开存放**：人设只影响语气与立场，事实只影响"知道什么"，
两者互不覆盖。

## 六·补四、群感知（1.4 起）

机器人在群里不只回答被 @ 的消息——它**尽量记住这个群本身**：
群里有谁跟它打过招呼、它自己在这个群叫什么、大家聊天的氛围。

### 平台限制与近似方案（先说清楚）

QQ 官方开放平台对群聊有**硬限制**，没有任何接口能拉取完整成员名单或群资料：

| 想知道 | 平台提供 | 本项目的做法 |
|---|---|---|
| 群成员名单 | ❌ 无接口 | 靠 `GROUP_MEMBER_ADD` 事件 + 每条 @ 消息累计「见过的人」，上限 500/群 |
| 群名称/群主 | ❌ 无接口 | 不存群名，用 openid 尾段标识；维护端可手动备注群名片 |
| 机器人自己的群昵称 | ❌ 无设置接口 | 聊天指令「叫你XX」+ 维护端手动设置，按群独立保存 |
| 全部群消息 | ⚠️ 需**群主逐群授权** | 授权后走 `GROUP_MESSAGE_CREATE` + 三级漏斗决定是否接话（见六·补五） |

因此「群里有多少人」的回答口径是**"跟机器人有过交流的约 N 人"**，
AI 提示词里也明确要求它不要编造群成员姓名。

### 事件接入（v4 intents）

订阅位在原有基础上新增 `GROUP_MEMBER_EVENT`（`1<<24`，官方 wiki 有定义、
botpy SDK 尚未收录的位），加上已订阅的 `GROUP_AND_C2C_EVENT`（`1<<25`）里的
全套生命周期事件：

| 事件 | 行为 |
|---|---|
| `GROUP_ADD_ROBOT` | 群档案建档；按设置发一句加群问候语（默认关闭，主动消息耗配额） |
| `GROUP_DEL_ROBOT` | 标记该群档案为不活跃（保留历史，不删数据） |
| `GROUP_MEMBER_ADD` | 新成员 openid 记入「本群见过的人」 |
| `GROUP_MSG_RECEIVE / REJECT` | 群主对「接收所有消息」的授权/撤销（同时控制主动发言）；撤销后不再接话与问候 |
| `GROUP_AT_MESSAGE_CREATE` | 发送者记入见过的人 + 刷新活跃时间（不论走规则还是 AI） |

Identify 被拒时按四级阶梯降级：完整订阅 → 去掉群成员事件位 → 仅消息 → 基础事件。

### 群档案进 AI 上下文

回复每条 @ 消息时，群画像（本群昵称、见过多少人、主动消息权限）
注入到提示词的 system 段——位置在事实之后、动态群背景之前，
内容短且极少变化，前缀缓存友好。

### 用户侧指令

- `叫你 XX` —— 设置机器人在**当前群**的名片（仅群聊有效，单聊会礼貌拒绝）
- `你叫什么 / 你是谁` —— 优先回答本群名片，没设则用官方名字
- `群里都有谁 / 群里有多少人` —— 报数量 + 列出报过名字的人，并说明还有多少人没报名

维护端在 **「AI」Tab → 群组** 里可以：开关/编辑加群问候语、
查看每个群的档案与成员样本、手动改群名片、删除群档案。
数据随 Room v4 增量迁移落库（老用户的身份/事实/人设全部保留）。

## 六·补五、群聊参与（1.6 起）

前面所有的能力都有一个前提：**只有被 @ 时机器人才知道群里发生了什么**。
1.6 起可以打开「接收所有消息」，让机器人像群友一样旁听并**有选择地**接话。

### 门槛在群主，不在开发者后台

这一点很容易搞错：开关**不在** QQ 开放平台后台，而在 QQ 客户端里、**按群独立**：

> 群设置 → 群机器人 → 本机器人资料页 → 把「机器人可获取的群聊消息范围」
> 改成「**获取群内全部消息**」

- 只有群主/管理员能改，每个群要单独开一次；
- 开启后平台回调 `GROUP_MSG_RECEIVE`，关闭回调 `GROUP_MSG_REJECT`——
  这两个事件本来就在订阅里，因此本项目的群档案字段 `proactiveAllowed`
  同时就是"该群是否已授权"的标志；
- 部分机器人需要企业主体认证，资料页里才看得到这个选项；
- 没授权时行为与 1.5 完全一致：只回 @ 消息，不会报错。

### 三级漏斗：为什么不是每条都回

一个活跃群一天几千条消息，每条都问模型既贵又慢，还容易被群友嫌吵。
因此判断分三层，逐层收窄：

| 层级 | 判据 | 成本 |
|---|---|---|
| 1. 频率 | 冷却（默认 45 秒，可调到 **1 秒**；按 5 分钟消息量自适应：热群 ×2、冷场 ×0.6）、每小时默认 60 次（**可设 0 = 无上限**）、每天默认 400 次（同样支持 0 = 无上限） | 零 |
| 2'. AI 主导（**默认**，1.9.2 起） | 规则层只挡明显噪音（单字、@别人、刷屏等强负分），**其余每条消息都交给模型判断**要不要接话——不再卡分数、不再按概率抽样；上下文（最近 8 条）与人设随请求携带 | 每条一次极小调用（maxTokens=8） |
| 2/3. 规则主导（关闭「让 AI 决定」时） | **本条消息**：疑问句 +25、长度适中 +10、@别人 −20、单字/表情 −20；**上下文信号**：话题延续 +15、有人在回应机器人 +15、冷场 +10、同一人刷屏 −10。达到阈值（默认 **15**）后按概率抽样（默认 35%，随人设性格浮动）直接接话，零模型调用 | 零 |

「让 AI 决定要不要接话」默认开启（AI 主导）；关闭则回到规则主导。

被叫到**群名片名字**时直接跳到接话（仍受 5 秒最小间隔与配额约束）——
群友叫了不理，比多回一句更伤体验。

热群放慢、冷场加快，这就是"看聊天频率"；疑问句加分、@别人减分，
就是"看聊天内容"。

> **1.9.3 起**：第二层里各情形的分值、阈值，以及 AI 判断的用户规则、
> 冒犯词表，全部可在「AI → 群聊参与」里调节（详见
> [六·补十一](#六补十一设置页重构与插话参数用户化193-起)）。

### 顺带变强的记忆

- 全量消息写进**群背景**，默认保留 **200 条**（注入提示词时仍只取 20 条，
  不撑爆预算）——机器人第一次能真正理解"刚才在聊什么"；
- 全量消息带 `author.username`，这是平台**唯一主动提供真实昵称**的场景，
  会按"平台昵称"优先级记进身份名录（不覆盖用户自称与人工备注），
  「群里都有谁」从此能报真名；
- 群里的普通发言也会参与事实抽取（纯正则，命中才落库）。

### 身份认知（1.7 起补强）

平台给的身份线索只有碎片，这一版把它们拼得更完整：

| 想知道 | 来源 | 处理 |
|---|---|---|
| 群里每个人叫什么 | `author.username`（全量消息）/ 「叫我X」/ 人工备注 | 按 人工 > 自称 > 平台 的优先级入库，注入提示词时只报真名 |
| 机器人在本群叫什么 | 群名片没有接口，但 @ 消息的 `mentions` 里可能带机器人自己的 username | 自动采纳为群名片；用户用「叫你X」或维护端设置过则永不覆盖 |
| 群里都有谁 | 事件累计 + 名字名录 | 群画像注入前 8 个真名 + "另有 N 位没报名"，并明确禁止编造 |
| 改名后还叫旧名字 | 历史对话里残留旧称呼 | 每轮提示词都声明"对方现在的名字是 X，以此为准；旧称呼一律作废" |

维护端「AI Tab → 群组」里每个群的成员样本会显示学到的昵称，
没学到的显示「群友 + openid 尾号」，不会再是一串纯编号。

### 成本与安全

- 参与默认**关闭**；关闭时全量消息只记记忆、不发言；
- 「插话前让 AI 判断」可以关掉，只保留规则 + 概率，零额外模型调用；
- 群主撤销授权（`GROUP_MSG_REJECT`）后立即停止接话；
- 回复走被动回复（带原消息 id），不消耗主动消息配额。

设置位置：**「AI」Tab → 群组 → 群聊参与**。

### 两级消息链路（1.7.1 起区分得更清楚）

机器人收到的群消息只有两类，处理方式完全不同：

| 类型 | 判定 | 处理 | 是否可能不回 |
|---|---|---|---|
| **@ 我的消息** | `GROUP_AT_MESSAGE_CREATE`，或全量消息的 `mentions` 含机器人 | 永远走完整回复链路（指令 → 规则 → AI） | 否 |
| **普通消息** | `GROUP_MESSAGE_CREATE` 且没有 @ 机器人 | 只入库记忆，再由三级漏斗决定是否接话 | 是 |

判断只针对**普通消息**——@ 是明确的对话邀请，不该再让模型猜"要不要理"。

### 群消息查看器（1.7.1 起）

「AI」Tab → 群组 → 每个群右侧的「**消息**」：实时显示机器人**听到**的内容，
与它理解群氛围用的是同一份数据（群背景，最多 200 条）。

每条消息都带两样东西：

- **类型标签**：`＠我`（红色）或 `普通`；
- **处理结论**：`已接话（规则 40 分）` / `不接：冷却中（45 秒）` /
  `不接：概率未命中` / `不接：AI 判断不需要接话` / `不接：群聊参与未开启` /
  `@ 了机器人，交给 @ 链路`。

所以"它为什么不理我"不用再猜——打开这个列表就能看到是没收到、被冷却挡住、
概率没过，还是模型判断不该插嘴。

列表为空时的提示会直接列出排查步骤（授权 → 发几条非 @ 消息 → 刷新），
并提醒「记忆 → 共享群聊背景」必须保持开启。

### 收不到全量消息时（排障顺序，1.7.2 起）

「AI」Tab → 群组 顶部新增**接收诊断**卡片，直接显示两类事件的到达次数：

```
@我消息：12 条 · 普通群消息：0 条
```

**@ 有、普通为 0 → 问题一定在平台侧，跟接话策略无关。** 按顺序检查：

0. **开放平台 → 开发设置 → 事件订阅与回调 → 接入方式必须选「WebSocket」**。
   选 Webhook 又没填回调地址时，平台会把事件推给一个不存在的地址，
   WebSocket 这边什么都收不到——这是最容易踩、也最难自己发现的一条；
1. 同一页的**接收事件配置**选「全部接收」；
2. **QQ 群设置 → 群机器人 → 本机器人资料页** → 「机器人可获取的群聊消息范围」
   改成「获取群内全部消息」（按群独立，只有群主能改）；
3. **重连一次**（停止再启动机器人），让新的订阅生效；
4. 在日志里搜「首次收到事件类型：GROUP_MESSAGE_CREATE」——
   没有这一行就说明平台还没推，代码侧无需再动。

两类都收到后，普通消息才会进入「群聊参与」的三级漏斗。

## 六·补八、被指名冒犯时按人设反应（1.8.2 起）

之前「阿远你是傻B吗」会被三级漏斗判成"不该接"——因为它按"没 @ 你就别插嘴"的
通用规则打分。但**被指名辱骂是例外**：装没看见比回错更伤人设。

### 冒犯检测（规则层，永远生效）

- **指名**：消息里出现机器人全名或名字后缀（"过去的阿远" → "阿远"）；
- **冒犯**：命中侮辱词表（含 sb / 沙比 等常见谐音缩写）；
- 两者**同时**成立才触发——"阿远今天没来"不会炸出来，
  "这游戏真垃圾"这种没名字的脏话也不会；
- 触发后**强制接话**（跳过概率与 AI 判断），只保留最小间隔防对骂刷屏；
- **@ 了别的群友**的消息直接让路：那是两个人的对话，再热闹也不插嘴。

### 反应与人设联动（提示词层）

触发时给模型注入一段"反应许可"：

> 刚刚「某某」当众骂了你：「原话」。这不是旁听，是冲你来的，必须按你的人设做出反应：
> 脾气暴躁的人设可以直接怼回去，阴阳怪气的人设可以冷嘲，温和的人设也可以冷处理。
> 你对「某某」的了解：……。熟人开玩笑和陌生人挑衅，反应程度应当不一样。
> 底线：不攻击家人、不威胁、不连续对骂，一两句到位即可。

所以「脾气不好被骂了骂回去」这类设定，只要写进人设（设置 → 人设）就会真正生效；
不同的人骂，反应也不同——模型会参考关于这个人的记忆事实。

### @ 链路同样生效

@ 机器人并带侮辱词（"你个傻逼"）时，@ 链路的回复也会带上"你刚被骂了"的上下文。

## 六·补九、评分体系与人设关联（1.9 起）

之前"直接喊机器人的设定昵称，机器人不理"——排查发现是三个 bug 叠加，
顺带把"要不要说话"和人设真正关联了起来。

### 1. 叫名字不回的三个根因（都已修）

| 根因 | 表现 | 修复 |
|---|---|---|
| 名字匹配只认**全名** `contains` | 设定「过去的阿远」，群友喊「阿远」永远匹配不上 | 共享 `BotNameMatcher`：完整名与 ≥2 字后缀都能命中（中文称呼习惯叫后两个字） |
| 群档案缺失 → 整条消息跳过 | 首条全量消息早于加群事件到达时，档案还没建，连叫名字都被"群档案不可用"拦掉 | 收到消息先记账，档案没有就**现建**；档案彻底缺失时回落官方名继续判断 |
| AI 未配置时静默丢弃 | Forced 命中但模型没配，什么都不发生（日志可见） | 保持现状，但群消息查看器的结论会显示"不接：AI 未配置" |

### 2. 人设驱动参与决策（三层联动）

参考 **HUMA**（arXiv 2511.17315，策略评分 = 适配度 + 时机）、
**Big Five 人格调制**（东京电机大学：外向人格更愿意打断与发言）与
**GroupGPT**（华东师大：廉价小模型先判时机，贵模型再生成）的研究结论：

| 层 | 机制 |
|---|---|
| 规则层（零成本） | `PersonaBias`：从人设提示词关键词推断性格——「话痨/健谈/外向」→ 打分阈值 −10、抽样概率 ×1.4；「高冷/寡言/惜字如金」→ 阈值 +10、概率 ×0.7；识别不出保持中性 |
| 模型层（AI 判断） | `shouldChimeIn` 现在携带当前生效的人设（按 人→群→全局 解析），并明确指示"按你的性格判断：外向爱聊的可以更主动，高冷话少的只在必要时接话" |
| 强制层 | 被叫名字 / 被指名冒犯仍然**必答**——人设只影响"旁听时插不插嘴"，不影响"被点名要不要理" |

所以「话痨」「高冷」这类设定写进人设后，插话频率会真的跟着变；
同样的群聊内容，不同人设的机器人会有不同的参与节奏。

### 3. 逻辑梳理结论

审查全链路后确认无其它逻辑问题：
配额检查 → 冒犯 → 名字 → 冷却 → 打分 → 概率 → AI 判断的顺序合理；
@ 别人让路优先于一切（不消耗配额）；全量与 @ 消息共享同一群背景作用域；
重复推送幂等。已知限制（有意设计）：名字/冒犯必答仍受每小时/每日配额约束。

## 六·补十、配置导入导出（1.9 起）

**设置 → 备份与恢复**：换机或备份用，走系统文件选择器。

- **导出**：生成 JSON（`qbot-config-日期.json`），包含机器人凭证、AI 接入（含 Key）、
  记忆/问候/参与配置、全部规则、全部人设、成员备注名、群名片；
- **导入**：按**合并**进行——同 id 规则覆盖、同名同绑定的人设更新提示词、

  这些是"运行数据"而非"配置"，搬过去反而会把旧设备的上下文带歪；
- ⚠️ 导出文件含**明文密钥**，请妥善保管。

## 六·补十一、设置页重构与插话参数用户化（1.9.3 起）

> 2.0.0 起，本文所述的折叠设置页与「AI Tab → 群聊参与」入口已改为
> **设置中心子页面**（见下一节）；参数本身与默认值不变，仅位置调整。

### 1. 设置页：从「一列拉到头的卡片」到可折叠分组

设置页曾经是七张卡串行的长滚动页（凭证 / AI 接入 / 记忆 / 运行策略 /
手动发送 / 备份恢复 / 使用说明），常用项被埋在最底下。现在：

- 全部卡片可折叠，**点标题栏收起/展开**；默认展开常用三张
  （凭证、运行策略、备份恢复），内容最长的 AI 接入与使用说明默认收起；
- 展开状态用 `rememberSaveable` 保存，旋屏不丢；
- 折叠组件（`ExpandableCard` / `ExpandableSection`）提为公共组件，
  「群聊参与」卡内部的高级分区同样复用。

### 2. 打分明细用户化（评分微调）

插话漏斗的规则打分过去是硬编码分值，现在 `ChitchatConfig.scoreWeights`
八个字段全部可在 **「AI」Tab → 群聊参与 → 评分微调** 调整：

| 情形 | 字段 | 默认值 | 范围 |
|---|---|---|---|
| 长度适中（2~60 字） | `lengthScore` | +10 | 0~20 |
| 疑问句 | `questionScore` | +25 | 0~40 |
| 单字/表情 | `shortPenalty` | −20 | −40~0 |
| @ 了别人 | `mentionPenalty` | −20 | −40~0 |
| 话题延续 | `topicScore` | +15 | 0~30 |
| 有人回应机器人 | `respondBotScore` | +15 | 0~30 |
| 冷场 | `quietScore` | +10 | 0~20 |
| 同一人刷屏 | `spamPenalty` | −10 | −30~0 |

- 过筛门槛 `minScore`（0~40，默认 15）一并开放；人设关键词
  （话痨 −10 / 高冷 +10）仍在其之上微调；
- 提供「恢复默认分值与门槛」一键复位；
- AI 主导模式（默认）下分数不再当门槛，只挡负分噪音——
  微调此时影响的是"噪音线"；规则模式下才是完整的过筛门槛；
- 全部持久化（DataStore），旧安装升级后按出厂值读取，行为不变。

### 3. AI 接话判断的用户规则

`chimeRules`：用户用自然语言约定"什么场合该接话"，
例如「群里讨论工作时不要插话」「有人求助时优先接话」「凌晨不要接话」。

- 注入 `AiResponder.shouldChimeIn` 的系统提示词，
  **优先级高于内置的通用 YES/NO 规则**；
- 上限 10 条、每条 100 字（防止把判断提示词撑爆，`MAX_USER_RULES` 兜底）；
- 设置位置：**「AI」Tab → 群聊参与 → AI 接话规则**。

### 4. 侮辱词表自定义

`insultExtraWords`：内置侮辱词表（傻逼/智障/废物等）之外，
追加自己群里的黑话与谐音（如「菜狗」）。「叫名字 + 这些词」同时成立，
才会触发按人设的冒犯反应。上限 50 个、每个 10 字。
设置位置：**「AI」Tab → 群聊参与 → 冒犯词表**。

### 5. 顺手开放的其它参数

| 参数 | 位置 | 说明 |
|---|---|---|
| 每天接话上限 | 群聊参与 | `maxPerDay`，此前只存不露 |
| 被叫名字必答 | 群聊参与 | `answerOnName`，此前只存不露 |
| 日志保留天数 | 设置 → 运行策略 | 1~30 天滑杆 |
| 每人事实条数 | 设置 → 记忆系统 | 5~50 条 |
| 群背景注入条数 | 设置 → 记忆系统 | 10~100 条 |
| AI 单次回复长度 | 设置 → AI 接入 | `maxTokens` 200~4000 |

以上全部随配置导入导出走；旧备份缺失新字段时按出厂值导入，向后兼容。

## 六·补七、群内指代与引用（1.8 起）

群里最常见的误解是「**他在骂谁**」。截图里那句「这个人是傻B」被机器人当成了骂自己，
根因不是"没读到全局消息"，而是缺三样东西：指代规则、被引用原文、对"我只看得到一部分"的自觉。

### 1. 群聊常识写进提示词

群聊场景下每条请求都会带一段固定规则（与人设无关，不受人设改写影响）：

> 消息里的「你」才指你；「他/她/这个人/那人/楼上/某人」通常指第三方，不要往自己身上套。
> 你只能看到 @ 你的消息（以及群主授权后的普通消息），看不到的部分不要编造；
> 对方指代不明时先问清楚，例如「说的是谁啊」。

### 2. 引用原文一起喂给模型

QQ 群里「回复某条消息」时平台会带 `reference_message_id`。现在会拿它去
200 条群背景里反查原文，注入成：

> 对方正在回复「阿远」的这条消息：我刚刚说什么了
> 判断「他/这个人/楼上」指的是谁时，优先看这条原文。

引用的原文只在**我们自己收到过**的消息里能查到；没收到的仍查不到——
但至少不会瞎猜。

### 3. @ 识别更宽容

- `mentions` 里比对 `id` / `member_openid` / `user_openid` / `union_openid` 四种字段；
- `<@...>` 剥离不再限定纯数字（openid 形态的 @ 也能剥干净）。

### 关于「程序里仿制全局消息」

**不可行，也不该做**。全局消息的唯一来源是平台推送；程序内"仿制"只能靠编造，
等于让模型凭空补上下文，幻觉会比现在严重得多。

可行的替代是**把已有的碎片拼成尽量完整的视野**：

| 碎片 | 来源 | 作用 |
|---|---|---|
| @ 我的消息 | `GROUP_AT_MESSAGE_CREATE` | 必须回的那部分 |
| 普通群消息 | `GROUP_MESSAGE_CREATE`（需两道开关） | 真正的群氛围 |
| 引用原文 | `reference_message_id` + 本地群背景 | 解决"他在说谁" |
| 群成员名册 | 事件累计 + 真实昵称 | 让模型知道"还有别人存在" |
| 明确声明"看不到" | 提示词固定规则 | 不确定时反问，而不是瞎猜 |

### 指令回复的人设化（1.5 起）

早期的指令回复是写死的固定句式（"你叫小明呀，我一直记得。"），
配上毒舌人设就是**人格分裂**。现在这些指令的回复分两层：

| 层 | 内容 | 触发条件 |
|---|---|---|
| 人设复述 | 指令结果作为**事实材料**连同人设提示词、记忆上下文交给 AI，让它用自己的语气说 | 复述开关开启（默认）且 AI 配置可用 |
| 固定句式兜底 | 此前的文案原样保留 | 复述开关关闭，或 AI 调用失败/返回空白 |

设计要点：

- **执行与表达分离**：改名片、删记忆等副作用仍在本地可靠完成，
  失败的只是"怎么说"，绝不影响指令功能本身；
- 给 AI 的事实材料是中性的（"对方的展示名是「小明」（对方自己告诉你的）"），
  并附任务说明：像本来就知道一样自然说出、不得编造关键信息；
- 会话历史只记录用户的原始话术，不记录「【指令结果】…」这类内部包装文本；
- 在 **「AI」Tab → 记忆 → 指令回复人设化** 可随时关掉，
  回到不消耗 API 的固定句式。

## 六·补六、人设进化（1.7 起）

写死的人设只会越来越不合身。现在可以让 AI 拿真实群聊当镜子，给自己改人设。

### 怎么工作

1. **触发**：人设卡片或全局提示词卡片上的「AI 优化」，可附一句额外要求
   （如"更毒舌一点，但别骂人"）；
2. **输入**：当前提示词 + 最近活跃群的 40 条群聊样本 + 额外要求；
3. **约束**：不换身份、不改价值观；删掉与样本冲突或空泛到无法执行的句子；
   补全口头禅、句子长度偏好与场景边界；
4. **校验**：输出 <20 字、>1500 字、或膨胀超过原文 1.6 倍 → 一律拒绝，保留原版；
5. **存档**：第一次优化前自动把当前版本存为「**初始版本**」（不可删除），
   之后每版都留快照（默认保留 20 条），可一键回滚。

> 为什么不做"每条消息后自动改人设"：人设频繁变动会让前缀缓存全部失效，
> 既慢又贵，模型也容易越改越飘。当前采用「手动触发 + 严格校验 + 可回滚」，
> 把进化频率交给用户判断。

设置位置：**「AI」Tab → 人设**（全局提示词与每条人设都有「AI 优化 / 版本历史」）。

## 六·补十二、设置中心子页面化 + 接话可训练闭环（2.0.0 起）

### 1. 设置页：从折叠卡片改为「设置中心 + 子页面」

2.0.0 推翻了 1.9.3 的折叠方案——七张卡即使折叠，仍是「一列长滚动 + 三层信息」。
现在：

- **首页只列入口**：按 接入 / 智能 / 工具 分组，每行右侧是实时摘要
  （AppID 尾号、模型名、已认识 12 人、已开启 · 规则 3 条……）；
- **点进去是独立子页**：顶部返回箭头 + 系统返回键（`BackHandler`）回首页；
- 子页内不再折叠，改为「分区标题 + 卡片」平铺；滑杆全部改为松手才落库，
  拖动时不再逐帧写 DataStore；
- 八个子页：机器人凭证 / 运行与保活 / AI 模型 / 记忆系统 / 插话与应答 /
  手动发送 / 数据与备份 / 使用说明；
- 插话参数（评分微调、AI 规则、冒犯词、加群问候语）从 AI 页迁入
  **设置 → 插话与应答**；AI 页只保留 记忆 / 人设 / 群组 / 接话复盘；
- 页面用 `SettingsEntry(id: String)` 注册表描述，
  `SettingsCatalog.all() = 内置页 + PluginHost.entries()`。
  **插件系统上线后，插件只需返回自己的条目，设置页的分发逻辑一行不用改。**

### 2. 接话可训练闭环

大模型无法在线训练权重，但可以「记住教训」。2.0.0 落了一条完整链路：

| 环节 | 实现 |
|---|---|
| 记录 | `chime_decisions` 表：群、发言者、消息、上下文摘要、规则分、命中路径、AI 判断 + 理由、最终动作、回复、是否 @ / 被冒犯 |
| 判断 | `shouldChimeIn` 返回 `ChimeVerdict(should, reason)`；提示词要求「第一行 YES/NO，第二行 ≤20 字理由」 |
| 反馈 | AI 页新增「接话」Tab：逐条展示判断，标「该说 / 不该说」；标错可填备注 |
| 反思 | 标错时立即调一次模型，把案例总结成 ≤40 字经验；相似经验（bigram 重叠 ≥0.6）更新而不是新增 |
| 注入 | 下次判断注入最多 8 条经验（本群优先、全局兜底）；优先级：用户规则 > 经验 > 通用规则 |
| 复盘 | 近 7 天判断数 / 反馈数 / 正确率 / 误接 / 漏接；经验库可编辑、停用、删除 |

- 经验带 `scopeGroupId`：A 群学到的「别插话」不会污染 B 群；
- 决策日志保留 7 天 / 最多 2000 条，启动时清理；
- 经验库上限 40 条，超出淘汰最久未更新的（2.1.0 起改为可调 20~200，见下一节）；
- 经验库进入配置备份（训练成果换机不丢），决策日志属运行数据不备份。

### 3. 为路线图预留的接缝

- **插件系统**：`SettingsEntry` 注册表 + `PluginHost` 空壳 + 单一
  `ChimeDecisionSink` 出口；未来插件页零改动接入，
  决策记录换成 `CompositeDecisionSink` 分发即可；
- **情绪值 / 好感度**：决策记录已带 `speakerId` / `insulted` / `addressed`，
  与 `ChitchatPolicy.observe` 同处一次遍历就能喂给新消费者；
- **热梗**：`BehaviorContext` 是提示词注入的唯一入口，新能力只扩字段、不改签名；
- **数据库版本**：本次 v7（`chime_decisions` / `chime_lessons`），
  情绪 / 好感预留 v8、插件 v9。

## 六·补十三、经验库目录化（2.1.0 起）

### 1. 为什么要改

2.0.0 的经验库是一列扁平淡句，去重只靠字面相似度。实际用起来有两个问题：

- **同义改写漏判**：「两人私聊别插话」和「别人对话时保持安静」字面重叠低，
  会被当成两条，同一件事越学越多；
- **单一场景占满提示词**：八条注入里可能有五条都在说「别插话」。

2.1.0 把它改成**带目录的结构**。

### 2. 固定类别目录

不再让模型自由生成类别（很快会漂移成几十个近义词），只允许八选一：

| 类别 | 含义 |
|---|---|
| `PRIVATE_CHAT` | 两人对话 / 一对一 |
| `COLD_START` | 冷场、抛话题 |
| `HELP` | 求助、提问 |
| `WORK` | 工作、正经话题 |
| `TIME` | 时段禁忌（深夜等） |
| `HUMOR` | 玩笑、玩梗边界 |
| `CONFLICT` | 争执、情绪 |
| `OTHER` | 兜底 |

反思时模型直接输出 `{"category":"...","text":"..."}`；解析失败会退回纯文本 +
关键词归类，不会因为模型不听话就丢掉一条经验。

### 3. 同类合并与归并

- 入库前先按「同群 + 同类别」取出同类经验，在**类别内部**做相似度比较
  （bigram 重叠 ≥ 0.45，比跨类别比较宽松）：命中就**改写原条 + 支撑数 +1**，
  不新增；
- 每条经验记 `supportCount`（被多少反馈支撑）与 `hits`（被注入几次）；
- **单类上限 6 条**：超出时触发一次「该类归并」——模型把同类多条压成 ≤3 条
  更概括的，支撑数求和后摊到新条目上；
- 容量淘汰按「支撑数低 + 最久未更新」优先，把真正有用的经验留住。

### 4. 注入侧的配额

- 每次判断注入条数可调（3~12，默认 8）；
- **同一类别最多占 3 条**，避免八条经验全在讲同一件事；
- 注入时带类别标签（`【两人对话】…`），模型能看出每条管什么场景。

### 5. 参数与界面

| 参数 | 位置 | 范围 / 默认 |
|---|---|---|
| 经验库容量 | 设置 → 插话与应答 → 训练与经验 | 20~200，默认 80 |
| 每次注入条数 | 同上 | 3~12，默认 8 |

复盘页按目录分组展示：`两人对话 · 3 条 · 支撑 7 次`，每条显示支撑与命中次数，
可编辑、停用、删除。经验库随配置备份（含类别与支撑数）。

### 6. 同时修复

- **`NetworkOnMainThreadException`**：复盘页提交反馈时，反思调用是从 UI 协程发起的，
  而 `LlmClient` 直接用了 OkHttp 的阻塞 `execute()`。现在客户端内部统一
  `withContext(Dispatchers.IO)`，「测试连接」等其它 UI 入口也一并受益；
- 备份页的 SAF 文件读写同样挪到 IO 线程，大备份不再卡界面。

### 7. 2.1.1 修复与增强

**a. 空正文：从「假装成功」改成「说清楚 + 自动重试」**

现象一：点「标错」提示 `NetworkOnMainThreadException` —— 已改为客户端统一切 IO。
现象二：提示 `响应中没有回复内容`，原始返回里 `content` 为空、只有 `reasoning_content`。

根因不止一个：反思调用没传思考开关（DeepSeek 默认开启思考，150 token 全被思维链吃掉）；
而 `LlmClient` 又把 `reasoning_content` 当正文兜底，等于"看似成功、内容其实是思维链"。

- 正文与思考过程彻底分开：`reasoning_content` 不再冒充答案，
  空正文抛专用 `EmptyContentException`（带 `finish_reason`，能区分"被截断"还是"没输出"）；
- 结构化短任务（反思/归并）按**任务画像**强制关思考、额度 400/500；
- 失败自动放宽额度重试一次，仍失败才报错；已标错的记录提供「重新总结」按钮。

**b. 判断上下文：之前确实"半闭着眼睛"**

三个叠加的问题：

1. **上下文被记忆注入开关误伤**：`recordChitchat` 与 `recentRoomMessages` 都要求
   `roomContextEnabled`，而这个开关的本意只是"回复时要不要带群聊背景"。一关，
   接话判断直接拿到空上下文（既不记录也不读）。
   → 记录/判断只受记忆总开关控制；`roomContextEnabled` 仅决定回复时是否注入。
2. **只喂 8 条、每条砍到 60 字、没有时间**：快群几秒钟刷满 8 条，模型看到的是断章；
   也看不出消息间隔，分辨不了"冷场"还是"两人快速对聊"。
   → 条数可调（6~24，默认 12），每条放宽到 120 字，并给每条标注相对时间；
   额外告诉模型「你上次在这个群发言是多久前」。
3. **复盘页看不到它当时看到什么**：`contextSnippet` 存了但没展示。
   → 决策卡里直接列出"它当时看到的"最近几条上下文。

提示词也补了判断方法：先读对话看"在聊什么、谁在跟谁说话、有没有人在等回应"，
两人快速互聊且没被提问倾向 NO，抛给全群的问题/冷场/延续自己的话题倾向 YES。

### 8. 2.1.2：判断失败不再吞掉原因

日志里出现 `群聊消息不接：AI 判断失败` 时，过去没有任何线索——异常被
`runCatching { ... }.getOrNull()` 吞掉了，只剩一句"失败"。

- 失败原因保留为一句人话：`HTTP 429` / `网络异常：timeout` / `超时`，
  同时写进日志（WARN）与决策记录的 `reason`，复盘页可以直接看到；
- 判断调用加 20 秒超时：判断是即时动作，超时就按不接处理，不再拖住消息处理；
- 新增用例模拟 500，断言记录里出现 `AI 判断失败（HTTP 500）`。

### 9. 2.1.3：生成额度统一跟随设置（含思考过程）

先厘清语义：`max_tokens` 统计的是**「思考 + 正文」的总和**，不是只算正文。
实测依据——额度给 40 时，`reasoning_content` 把额度吃光，`content` 为空、
`finish_reason=length`。如果只算正文，40 写一句理由绰绰有余，不会截断。

因此不再在代码里给判断/反思/归并各立一个隐藏数字，统一取设置里的
「单次生成上限」（200~4000，上限压到 8000）：

- 判断、经验反思、同类归并都用同一个额度；
- 被截断（`finish=length`）时自动翻倍重试一次，仍失败才按不接处理；
- 设置页改名「单次生成上限（含思考过程）」，并在**思考模式 + 额度 < 800** 时
  直接给出红色提示：正文可能被思考挤掉；
- 新增用例：额度 500 时请求体里就是 `max_tokens: 500`（不再有隐藏数字）。

用思考模式的群建议 ≥ 800；关闭思考时 300~800 足够。

### 10. 兼容

数据库 v7 → v8：`chime_lessons` 增加 `category` / `supportCount`，
老经验归入「其他」、支撑数按 1 计，不做破坏性迁移。

## 六·补十四、判断改成「想不想」+ 对话对象推断（2.2.0 起）

### 1. 从「应不应该」到「想不想」

原来的判断问的是"这条消息是否需要你接话"——这是个客服口径，模型会倾向于
给出"礼貌但正确"的答案，表现出来的就是：要么过度保守，要么说些没味道的场面话。

2.2 改成问"你此刻想不想接这一句"：

- 明确告诉模型：**你不是客服，也不欠任何人回复**，安静很正常；
- 想接的信号换成人的动机：被话题勾住、想吐槽、想补充、想纠正、冷场想救场、
  按性格忍不住；
- 不想接的信号也换成人的顾虑：两人在互聊、刚说完再说像刷屏、"只是可以回"；
- 人设不再只是"外向就多接话"，而是作为"这个人会不会被这种话题勾住"的依据。

### 2. 对话对象推断

同一句话，对谁说决定了该不该插：

| 信号 | 推断 |
|---|---|
| @ 了机器人 | `BOT`（对你说） |
| @ 了某个成员 | `MEMBER`（对「某某」说） |
| 引用了机器人的消息 | `BOT` |
| 引用了某人的消息 | `MEMBER` |
| 开头叫了某人的名字 | `MEMBER` |
| 上一条是提问、本条很短 | 在回答那个人（或机器人） |
| 都对不上 | `GROUP`（对全群说） |

推断结果会写进提示词（"这句话是对「阿远」说的，别人之间的对话插进去通常很怪"），
也存进决策记录，复盘页显示"它以为：这句话是对「阿远」说"——判断错了能一眼看出
是"对象认错了"还是"意愿判断错了"。

实现只用确定性证据（@、引用、称呼、问答相邻），不做猜测式画像；
`AddresseeDetector` 与提示词解耦，便于以后接入更好的推断。

### 3. 关于 dsh-bridge

顺带调研了最近流行的 dsh-bridge：它是 DeepSeek Harness 的**远程接入插件**
（二维码、隧道、IM 桥接、访问门禁、账号级人设隔离），群聊部分只有
"@ 才响应 + 发件人白名单"，**没有**拟人化、意愿判断、对话对象理解这类行为层设计。
唯一可借鉴的是"每个账号/会话独立上下文"，这一点本项目已有（按人/按群隔离）。

### 4. 兼容

决策记录新增 `addresseeKind` / `addresseeName`，Room v8 → v9 增量迁移；
复盘页对老记录不显示对象行（字段为空），不影响使用。

## 六·补十五、人格自主养成（2.3.0 起）

### 1. 这是改造，不是新增

项目里本来就有 `PersonaEvolver`（带边界校验）、`PersonaSnapshot`（版本快照 + 回滚）、
`evolvePersona`（手动「AI 优化」）。缺的只有两件事：

- **能从零开始**：`require(current.isNotEmpty())` 与「原文 × 1.6」的膨胀限制，
  让"白纸起步"根本走不通；
- **能自己触发**：只挂了一个手动按钮。

所以 2.3.0 没有另建一套「自主人格系统」——那会变成两套人格、两处提示词注入、
两个快照体系。做法是把 `AiConfig.systemPrompt` 这一个字符串**升格为「人格档案」实体**，
让存量的三件套继续工作，只补破壳与自动微调。

### 2. 人格是五段结构

```
[身份]     我是谁 —— 逐字锁定，自动成长永不修改
[性格]     3~5 个特质
[说话方式] 句长、口头禅、标点习惯、是否用表情
[兴趣]     会主动聊的话题类型（禁止写具体人名/群名）
[边界]     不聊什么、被冒犯怎么反应、不冒充群友
```

固定分段不是审美选择：

1. **可锁定**：[身份] 段代码级逐字比对，改了直接拒绝——靠提示词说"别改身份"实测会漂；
2. **可 diff**：段落级比较是 O(5)，成长日记能直接说"这次补了 [说话方式]"；
3. **可限额**：单段可单独约束，避免某一项吃掉全部预算；
4. **缓存友好**：人设是第一条 system，身份段稳定 → 前缀缓存至少前 N 个 token 稳定。

### 3. 性格种子：避免长成"群聊的镜子"

纯从群聊归纳，得到的是群聊的镜像——群里爱刷梗它就刷梗，群里冷淡它就哑巴。
新建人格时从 8 个原型里抽一个作为原点，群聊只负责把细节长出来：

| 种子 | 插话偏置 | 一句话 |
|---|---|---|
| 热心老哥 | 话痨 | 自来熟，见人有难处就想帮 |
| 毒舌损友 | 中性 | 刻薄但讲义气，损完就撤 |
| 高冷旁观者 | 高冷 | 惜字如金，被点名才答 |
| 好奇宝宝 | 话痨 | 连环短问句，不装懂 |
| 冷面笑匠 | 中性 | 一本正经讲怪话，不解释笑点 |
| 元气团宠 | 话痨 | 情绪外放，负责救冷场 |
| 考据党 | 中性 | 先纠正前提，再给结论 |
| 乐子人 | 话痨 | 爱起哄，见好就收 |

种子的 [性格] 文案必须命中 `PersonaBias` 的关键词表，否则"性格影响要不要说话"
会**静默失效**——测试逐条断言这一点。

### 4. 三个阶段与触发条件

```
EMBRYO ──破壳──▶ GROWING ──成长 8 次──▶ MATURE（间隔翻倍）
                    ▲
                MANUAL（用户手写的：不自动改）
```

| 动作 | 条件 |
|---|---|
| 破壳 | 新增消息 ≥ 60 条，或 ≥20 条且出生满 30 分钟 |
| 成长 | 新增 ≥ 150 条 **且** 距上次 ≥ 12 小时 |
| 低频兜底 | 新增 ≥ 40 条 且 距上次 ≥ 7 天 |
| 暂停 | 冻结 / 关开关 / AI 未就绪 / 人设是 MANUAL |

「新增消息」用**游标**（`personas.msgCursor` → `countSince`）而不是时间窗：
三天不开机、一开涌进 500 条时，时间窗会骗着连跑多次成长。

取样**跨 3 个活跃群各 16 条**——只取最近一个群，人格会变成那个群的镜子。

### 5. 四道安全边界

1. `[身份]` 段逐字比对，不一致直接放弃；
2. 2-gram Jaccard 相似度 ≥ 0.85（改动 ≤15%），且单次最多改 2 段；
3. 黑名单词 + 总长 120~1200 字；
4. **DB 级 CAS**：写回带 `WHERE updatedAt = :expected`，用户手改过就丢弃本次成长。

破壳/成长都是**成功才写快照**，不存在"快照里有、实际没生效"的幽灵版本。

### 6. 提示词解析链

| 级 | 条件 | 说明 |
|---|---|---|
| 1 | 绑定到这个人 / 这个群 | 覆盖层，最高优先 |
| 2 | 当前激活档案（`activeSlot = 1`） | 正文为空时用种子骨架 |
| 3 | 旧兜底 | 仅兼容场景 |
| 4 | 种子骨架 | **永不返回空** |

第 4 条是关键：空 system 会让 `PromptAssembler` 整条不注入，
模型立刻退化成"助手腔 + Markdown 标题 + 复读群友"。

### 7. 界面

- **AI → 人设**：当前人格卡（阶段 / 种子 / 成长次数 / 五段正文 / 上次改了什么），
  操作有编辑、成长日记、立即成长、换种子、冻结、交给它自己养；
  下面是未生效档案（切换 / 复制 / 删除）与折叠的「按人或按群单独设定」。
- **设置 → 人格成长**：自动成长开关、破壳消息数、成长消息数、最小间隔。
- **设置 → AI 模型**：原来的系统提示词输入框已移除，改为指向人设页的说明。

### 8. 迁移与兼容

- Room v9 → v10：`personas` 加 11 列 + `activeSlot` 唯一索引；
- 旧的无绑定全局人设 → 升格为档案并激活，**标 MANUAL**（手写的不自动改），
  同时补一条 INITIAL 快照，保证升级前的版本可回滚；
- 旧 `AiConfig.systemPrompt`（≠ 出厂默认）→ 启动时一次性导入为档案，用 DataStore flag 保证幂等；
- 备份新增 `persona_profiles` / `persona_growth`；旧备份导入时优先用全局人设行或
  `ai.system_prompt` 还原成档案，两者都没有则**保留本机现有档案**。

### 9. 下一版：多机器人

本轮把数据模型备好了，2.4.0 再做并发运行：

- `SettingsRepository(context, namespace)`：拆掉 `preferencesDataStore` 委托，改用工厂；
- 每实例一个 `qbot-<id>.db`（Entity/DAO 零改动，三张自然主键表天然不冲突）；
- `BotInstance(id, name, credentials, activePersonaId, dataScope)`，创建时选人格 + 选数据；
- 一个 `BotForegroundService` 管 N 个 Controller（通知聚合、watchdog 遍历）；
- UI 用 `CompositionLocal` 注入当前实例。

## 六·补十六、节奏交给模型 + 群上下文补全（2.3.1 起）

### 1. 去掉「节奏」滑杆

2.3.0 让用户调「破壳多少条 / 成长多少条 / 间隔几小时」，本质上是在让人猜一个
没人知道答案的数字：设大了冷清群永远不长，设小了热闹群一天改八次。

2.3.1 改成：

| 环节 | 谁决定 |
|---|---|
| 什么时候看一眼 | 本地：有新消息就够了（成长期 ≥10 条） |
| 值不值得改 | **模型**：读完这批对话，觉得没新东西就回 `NO_CHANGE` |
| 改多少 | 守卫：最多两段、幅度 ≤15%、身份段锁死 |

两次询问之间有冷却（破壳 30 分钟 / 成长 1 小时，进程内计时），
模型回 `NO_CHANGE` 时只推进游标、不写快照、不算一次成长。

设置页现在只剩一个开关和一段说明——**没有阈值要你调**。

### 2. 「手动设定」是什么

它就是**你手写的完整人格正文**，和旧版的「系统提示词」是同一样东西：
升级时如果检测到旧 `AiConfig.systemPrompt` 不是出厂默认值，会原样导入成一份档案，
并标为 `MANUAL`。

标 MANUAL 是保护：**用户亲手写的东西不被后台悄悄改写**。
想让它自己长，在人格卡或「设置 → 人格成长」里点「交给它自己养」——之后转成 `GROWING`，
从当前消息位置开始累计。

新建的人格默认是 `EMBRYO`（全自动），不会出现 MANUAL。

### 3. 群上下文缺口（真 bug）

过去只有「旁听」链路会把消息写进 `room_messages`：

- `@` 机器人的消息**完全没记**；
- 规则回复、指令复述的机器人回复也没记。

结果就是「@ 过但没回成」的那句话，在后续插话判断和回复的上下文里根本不存在——
模型看起来像"没看见别人刚刚叫过它"。

修法：

- `processMessage` 在处理 `GROUP_AT` / `GUILD` 前先 `recordChitchat`；
- `sendReply` 作为**群内回复的唯一出口**统一写 assistant 消息
  （旁听链路原有的重复写入已删除）。

现在群上下文里"问"和"答"都在，包括那些它当时没接的话。

### 4. 其他

- 人格卡整张可点（过去只有底部「编辑」按钮可点，点卡片没反应，像是卡死了）；
- 设置页「人格成长」里，MANUAL 人格直接给「交给它自己养」按钮；
- 备份里的三个节奏字段保留读取但不再生效（旧备份不报错）。

## 六·补十七、两条路并存：自动养成 / 自己写（2.3.2 起）

2.3.0 把「系统提示词」升格成人格档案时，顺手把"用户自己写一段"这条路砍成了
"只能写五段结构"，这是错的。2.3.2 起两条路都通：

| 路径 | 怎么进 | AI 会改吗 |
|---|---|---|
| **让它自己长** | 新建人格 → 选性格种子 | 会。破壳后按群聊自己微调 |
| **我自己写** | 新建人格 → 我自己写；或编辑现有档案正文 | 不会。等同旧版系统提示词 |

### 自由文本是被一等公民对待的

- **显示**：`[身份]…` 五段能解析就分段显示；解析不出来就**原样显示全文**。
  （2.3.1 及以前解析失败会回落到种子骨架展示，等于把用户写的东西藏了起来。）
- **注入**：`PersonaResolver` 直接返回档案正文，不要求任何格式。
- **安全**：保存时如果正文不是五段，`PersonaRepository.save` 会把 `stage` 强制降为
  `MANUAL`——自动成长拿不到可比对的段落，下一次只能整段重写，等于把用户写的东西冲掉。

### 随时互换

人格卡底部：

- 自动人格 → 「改为手动」：保留当前正文，停止自动成长；
- 手写人格 → 「交给它自己养」：转成成长期，从当前消息位置开始累计。

所以"先自己写一版，观察几天，再交给它自己长"是可行的工作流。

### 关于「自动成长」开关（2.3.3 已删除）

它和「冻结」是同一件事：都表示"这份人格别自动改"。在只有一个激活人格的前提下，
两个开关分处两地，只会让人怀疑"是不是有一个没生效"。所以删掉全局开关，
只保留逐人格的「冻结」——它更精确，人设页与成长页都能操作。

判断依据收敛成三层，不再重叠：

| 层 | 谁决定 |
|---|---|
| 这份人格要不要自动长 | 用户：冻结 / 解冻 |
| 这一批消息够不够看 | 本地：≥10 条（成熟期 20） |
| 看了要不要改 | 模型：NO_CHANGE 或小步改 |

### 关于旧版入口

`AiConfig.systemPrompt` 不再单独编辑——它已经变成人格档案的正文。
「设置 → AI 模型」里原来的输入框换成了指向人设页的说明，避免同一份人格有两处真相。

## 六·补十八、2.3.4 体检修复

一次全量审计里修掉的确定问题（其余低优先级项见仓库 issue 规划）：

1. **群内问答重复写入**：2.3.1 加了 `recordChitchat` + `sendReply` 记账，但三处回复
   仍调 `recordExchange`，导致一轮 @ 交互落 **4 行**（用户/机器人各两遍），
   200 行窗口实际只剩 100 轮。改为单聊才走 `recordExchange`。
2. **判断链路没关思考**：`wantsToChimeIn` 沿用了全局 `thinkingMode`，
   开思考后思维链吃掉输出额度，判断必然落空 → 全群静默。改为与其他结构化短任务一致强制关闭。
3. **停止机器人后仍在成长**：调度 Job 被丢弃，`stop()` 不取消它，后台每 10 分钟
   仍读库、调模型、写快照。现随 start/stop 启停。
4. **破壳游标越过未分析的消息**：游标取在模型调用之后，破壳那几十秒的消息既不进样本
   也不进下一批。改为样本之后、模型之前取。
5. **时间回拨会让成长永久停摆**：`now - lastAskedAt` 为负时恒小于冷却。负值现视为已过期。
6. **手动催一次后 10 分钟又自动跑一次**：`force()` 不刷新冷却。已补。
7. **重抽种子后旧骨架仍可回滚**：`reseed` 不删 INITIAL。已清。
8. **手动破壳可能留幽灵快照**：忽略 `commitBirth` 返回值。已按结果决定。

  无规则时不出现规则块、超过 10 条截断
- **接话可训练闭环（2.0.0）**：三条路径都留结构化记录（概率未命中 / AI 判断不接 /
  接话成功）、YES/NO + 理由解析（同行写法、垃圾输出按不接兜底）、
  经验注入与 8 条上限、经验清洗（编号 / 引号 / 超长截断）、
  相似经验去重、按群作用域注入与命中计数
- **消息分流与结论**：@/普通消息的标记与结论回填、群聊回复不重复写用户消息、
  @ 消息永不走漏斗判断
- **群内指代**：群聊常识注入（「你」才指你、指代不明先问）、引用原文注入、
  引用 id 解析、非数字 @ 标记剥离
- **身份认知**：mentions 里的群昵称采纳与不覆盖手动设置、群画像名册注入、
  改名后旧称呼作废声明
- **人设进化**：正常改写、代码围栏清理、过短/过度膨胀的输出被拒绝、样本进入请求体
- **BotRuntime 集成**：日志展示展示名而非 openid、记忆指令由 LLM 按人设复述、
  关闭复述开关走兜底文案、不同人的会话线程隔离但共享群聊背景、
  群事件经 onRawEvent 的端到端链路
- **网关集成测试**：用 MockWebServer 模拟平台，跑通 `建连 → Hello → Identify → READY → 事件分发`，
  并验证 `op7` 会触发自动重连、`op9`（Identify 被拒）会触发四级降级而非死循环
- **限频回归测试**：`/gateway/bot` 返回「接口调用超过频率限制」时进入冷静期，
  重连不再重复请求该接口（地址缓存复用）
- **Intents 降级测试**：完整订阅被拒 → 去掉群成员事件位 → 仅消息 → 基础事件逐级降级，全拒才停机并给平台指引

> 关于「连接中 / 鉴权中反复横跳」：真实故障的根因是 **Intents 位定义与官方不一致**
> （携带了服务端未定义的位），Identify 被拒后旧实现无脑重连形成死循环。
> 现已按官方 SDK（botpy）定义重写全部位，并增加三级降级；服务端拒绝的信号是
> **op9 消息**而非关闭码，两者都会触发降级。

> 关于「重连中 / HTTP 400 接口调用超过频率限制」：官方对 `GET /gateway/bot`
> 限频严格，早期版本每次重连都重新取地址，几十秒内就会打满频控并锁死在重连循环。
> 现已改为**取到地址即缓存复用**，只有握手被拒（401/403/404/410）才重新获取；
> 万一仍触发限频，会自动把重连间隔拉长到分钟级等待恢复。

## 八、已知限制

1. **机器人只能在其已被添加的群里工作**；单聊需用户主动发起（平台规则）。
2. **未认证机器人仅管理员可用**，且只能加入你作为群主的群。个人认证后上限 500 个群。
3. **主动消息有配额**，规则自动回复走"被动回复"通道不占配额，手动发送会占用。
4. **凭证不含群管理类高级能力**（如主动踢人、改群公告），如需请自行扩展 `OpenApi`。
5. **平台不提供群成员名单 / 群资料查询**，群感知只能靠事件累计近似：
   「见过的人」只覆盖与机器人有过交集的成员，每群上限 500 个样本。
   **未被 @ 的群消息默认收不到**，需要群主逐群授权「获取群内全部消息」；
   未授权时群氛围仍靠参与过的对话近似。
6. **AI 调用按 token 计费**，由你填写的服务商收取；群聊里 `AI 优先` 模式下每条消息都会请求，
   建议日常用「规则优先」或「仅 /ai」，需要时再切换。群聊参与额外产生少量判断调用
   （每条候选一次，`maxTokens=8`），可在设置里关闭「插话前让 AI 判断」。
7. `specialUse` 类型的前台服务在 Android 14+ 需要在 Manifest 声明用途（已配置），
   上架 Google Play 需要额外说明，自用无影响。
